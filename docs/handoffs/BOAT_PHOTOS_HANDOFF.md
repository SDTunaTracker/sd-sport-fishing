## Context

16 boats were missing photos (`boat_profiles.photo_url` null / no file in `web/images/boats/`). All 16 are **Fisherman's Landing** boats. The scraper (`src/scrape_boat_photos.py`) missed them because FL boat pages serve the photo as a plain `<img src="graphics/boats/<file>_large.jpg" alt="<Boat>">` tag with **unpredictable filenames** (`constition_boat1`, `IMG_3201`, `ExceL_new2`, `Pegasus2014`, …), while the scraper's `_scrape_fl_boat_page()` only looks for a `div.feature-img` CSS background-image (with a weak `<img>` fallback that isn't catching these).

The correct photo URLs were already located and verified (each returns HTTP 200 / image/jpeg). They're hard-coded in `scripts/fetch_missing_fl_photos.py`.

## Pattern of the live data (don't break it)

- `boat_profiles` is upserted by `_upsert_profile()` keyed on `(boat, landing)`; `photo_url` stores the **local** path `images/boats/<safe>.jpg` (`_safe_filename()` = lowercase, spaces→`_`).
- `download_boat_photo(boat_name, photo_url)` saves the file to `web/images/boats/` and returns that relative path.
- `web/data.js` (and `web/sitemap.xml`) are regenerated by `python -m src.main --export-only` — the front end reads `window.SD.BOAT_PROFILES[name].photoUrl`.
